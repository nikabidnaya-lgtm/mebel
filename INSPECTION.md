# Инспекция текущего лога и исправления

## Что показал новый лог

### 1. Проблема `0 аналогов` частично снята, но выявились новые дефекты
- Для `riva /catalog/kresla/` лог уже показывает `100 товаров`, то есть общий сбор больше не пустой.
- Значит корневая проблема с полностью пустым пулом была не единственной; теперь видно, что узкое место сместилось в качество ссылок и структуру категорий.

### 2. `missing_title` на Profoffice указывает, что собирались не карточки товара, а лишние ссылки
Признаки из лога:
- `profoffice/catalog/offices/: {'missing_title': 100}`
- `profoffice/catalog/waiting_areas/: {'missing_title': 99, 'product_error': 1}`
- `profoffice/catalog/chairs/: {'missing_title': 100}`

Это типично для ситуации, когда парсер попадает не на карточки товаров, а на разделы, подборки или промежуточные посадочные страницы.

### 3. `ERR_FAILED` на отдельных карточках нужно считать рабочим шумом
Одиночная ошибка вида:
- `Page.goto: net::ERR_FAILED`

не должна валить весь пайплайн. Нужна обработка на уровне карточки и продолжение сбора остальных ссылок.

### 4. Самый большой резерв ускорения — скрапить не всё подряд, а только нужные категории
Поскольку входной Excel уже содержит названия и описания товаров, можно сначала автоматически определить категорию каждого товара, а затем:
- строить план скрапинга только по нужным категориям;
- один раз собирать пул аналогов в рамках категории;
- переиспользовать этот пул для всех товаров той же категории.

## Что изменено в новой версии скрипта

1. Добавлена авто-классификация товаров из Excel по категориям.
2. Введён план скрапинга только по нужным категориям сайтов.
3. Добавлен дисковый кэш категорий, чтобы при повторных запусках не тянуть один и тот же каталог заново.
4. Добавлен кэш изображений и perceptual hash, чтобы не скачивать и не хэшировать одинаковые картинки много раз.
5. Ужесточена фильтрация товарных URL, чтобы сократить число ложных ссылок на Profoffice.
6. Ранжирование теперь идёт в пределах релевантной категории, а не по общему пулу со всех сайтов.
7. Фото-сходство считается только для текстового top-N, что ускоряет обработку.
