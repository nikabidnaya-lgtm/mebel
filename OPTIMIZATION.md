# Оптимизация скрипта подбора аналогов

## Что тормозило раньше

1. Скрипт скрапил все стартовые категории всех сайтов, даже если в Excel не было товаров из этих классов.
2. Для каждого товара ранжирование шло по общему пулу, а не по релевантной категории.
3. Одни и те же категории заново обходились при каждом новом запуске.
4. Картинки скачивались повторно без локального кэша и без кэша хэшей.
5. На Profoffice собирались многие ссылки не на карточки, а на промежуточные разделы, из-за чего лог показывал `missing_title`.

## Что внедрено

- **Категоризация входных товаров**: сначала каждому товару назначается категория по названию и описанию.
- **План скрапинга только по нужным категориям**: скрипт обходит только те категории сайтов, которые реально нужны для текущего Excel.
- **Переиспользование пула внутри категории**: если 10 товаров относятся к одной категории, скрапинг категории делается один раз.
- **Дисковый кэш категорий**: результаты категории сохраняются в `cache/categories/*.json`.
- **Кэш изображений и perceptual hash**: изображения и phash переиспользуются между товарами.
- **Двухступенчатое ранжирование**:
  1. быстрый текстовый скоринг;
  2. фото-сравнение только для top-N кандидатов.
- **Более узкие фильтры URL карточек**: уменьшает попадание ссылок на разделы вместо товарных страниц.
- **Буферизация результата**: сначала собирается весь пул аналогов по категориям, затем одним проходом формируется итоговый Excel.

## Дополнительные идеи на будущее

- Добавить TTL кэша, например 7 дней.
- Сохранять HTML карточек в debug-режиме для проблемных сайтов.
- Поддержать отдельные селекторы цен для каждого сайта после разового ручного осмотра DOM.
- Ввести white-list брендов/серий для более точного матчинга офисной мебели.
